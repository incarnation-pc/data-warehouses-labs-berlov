## Выполнение

Среда выполнения: Windows, PostgreSQL 17.11, MongoDB Community 8.0.4, mongosh 2.3.3, Neo4j Community 5.26.0 и Java 21. Для задания Git установлен переносимый Atom 1.60.0; GitHub используется как веб-сервис.

```powershell
psql -h 127.0.0.1 -p 55436 -U berlov -d berlov_labs -v ON_ERROR_STOP=1 -f data-vault/01_schema_and_data.sql
psql -h 127.0.0.1 -p 55436 -U berlov -d berlov_labs -v ON_ERROR_STOP=1 -f data-vault/02_verify.sql
mongosh mongodb://127.0.0.1:27028 --quiet --file mongodb/01_examples.js
```

Neo4j Browser: `http://localhost:7476/browser/`, Bolt: `bolt://localhost:7689`.
Последовательно выполнить `01_lecture.cypher`, `02_social_graph.cypher`, затем запросы `03_queries.cypher`.
Для просмотра графа: `MATCH p=(:Berlov6)-[]->(:Berlov6) RETURN p;`.

Порты относятся к локальным учебным экземплярам. Для другой установки укажите свои адреса подключения.
SQL пересоздаёт только схемы `berlov6_3nf` и `berlov6_dv`; MongoDB работает с `berlov6_mongodb` и отдельной временной базой; Cypher очищает только метки `BerlovLecture` и `Berlov6`.

## Модели

В 3НФ пять таблиц: факультет, группа, дисциплина, семестр и учебный график. Нагрузка относится к сочетанию группы, дисциплины и семестра. В Data Vault четыре Hub, два Link и пять Satellite. Спутники сохраняют версии описательных атрибутов; представление `current_study_plan` выбирает последнюю версию.

Социальный граф описывает учебное сообщество. Персонажи вымышленные, аватары условные. Выделены новички, наставники и организаторы. Узлы Person, Community, Event, Venue связаны отношениями MEMBER_OF, ATTENDS, KNOWS, ORGANIZES, TAKES_PLACE_AT и MENTORS.

За основу состава заданий и оформления взят предоставленный учебный пример. SQL, MongoDB и Cypher выполнены в отдельных локальных базах; снимки отчётов отражают текущий запуск.
